# Vitrine capability map

## Capability map

| Layer | Purpose | Example usage |
|---|---|---|
| Core | Shared technical standards | versioning, cache, security |
| Stack adapter | Project-specific implementation | Node/Express, Mongo, frontend |
| Vitrine | Visible project overview | roadmap, modules, decisions |

## Active repo view

This repo currently demonstrates:

- modular backend architecture
- service + model + lib split
- public storefront + admin area
- role-based access control
- optional integrations
- release-friendly structure
- project documentation that acts as a Vitrine

## Use in other repos

To reuse this kit in another repository:

1. keep the same core standards
2. map the stack
3. replace or add module files
4. update the project showcase
5. keep versioning and cache policy active

## Decision principle

The Vitrine is not a dashboard only; it is the system that turns technical work into reusable delivery knowledge.
